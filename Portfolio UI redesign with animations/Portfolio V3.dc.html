02 Exploring beyond my field

I don't like limiting myself to what I already know. I'll get my hands dirty with app development, game development, cloud technologies, creative tools and other areas outside my core expertise — even when I'm still a beginner. For me the goal isn't to know everything; it's to keep learning by actually building.

03 I learn by doing

Rather than waiting until I'm "good enough" to start something, I prefer jumping in, experimenting, breaking things and figuring them out along the way. Every project gives me a new skill, a new perspective, or sometimes just a really interesting problem to solve.

04 Always building

I'm interested in the intersection of AI, software, creativity and product development. Whether it's a web app, an AI system, a mobile app or a game — if an idea excites me, I want to build it.

01.5 / The rabbit hole

I've always been curious about how things work.

Long before I studied Computer Science I was experimenting with technology on my own — Windows, Linux and macOS, software and hardware alike, learning most of it by trying, breaking, researching and fixing.

That curiosity is what made me. It always started the same way — open it up.

> i wonder if i can
└─ squeeze more FPS out of a game
└─ optimize the whole system
└─ troubleshoot a stubborn Windows install
└─ open up the hardware
└─ replace the thermal paste
└─ find what is really going wrong
└─ work around software limitations
└─ modify games
└─ touch things I was not supposed to touch
> so how does this actually work?
└─ Windows, Linux and macOS — all three, on purpose
└─ break it, research it, fix it, repeat
└─ then stop patching other people’s software and write my own
// i don't always know the answer when i start I just know I'll figure it out.
